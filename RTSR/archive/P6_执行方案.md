## 1.1 满意率口径（2026-11-03 修正，重要）

> **论文的定义**：帧在基站缓冲里等待超过 **10 ms** 就被丢弃；成功帧 = 交付且没被丢。
> 端到端时延**不是**判据（空口传输时间不计入）。

**我们的实现对应关系**：

| 论文机制 | 我们的实现 | 状态 |
|---|---|---|
| 视频承载 PDB = 10 ms | `EpsBearer::NGBR_LOW_LAT_EMBB`（QCI 68）的 QoS 表里就是 10 ms，`lte-enb-rrc.cc:441` 把它写进 RLC | ✅ 本来就有 |
| 超时丢弃 | ns-3 `LteRlcUm` 的 PDCP discarding（默认开）：新 SDU 到达时若队首等待 > 10 ms 则丢弃；**加上我们之前补的 `return` 才真正不入队** | ✅ 本来就有 |
| 成功帧统计 | **每 UE：`FSR = complete / sent`**（`sent` 来自帧源的 `framesSent` 基线）| ✅ 本次修正 |
| 端到端时延 | 仅作对照列（`mean_fsr_e2e`），**不再作为满意判据** | ✅ 本次修正 |

> **修正前**用的是端到端口径（`within_pdb`，含空口传输），把传统方案的 41.7 KB 大帧
> 系统性判死：6 UE/cell 时报 35.7%，而按论文口径是 **96.8%**。
>
> **本次改动**：
> 1. 帧号全局唯一：`frameId = (ueIndex << 20) | 序号`，RLC 丢弃可归属到 UE；
> 2. 每 UE 汇总文件 `frame_per_ue.csv`（`ue,port,sent,seen,complete,in_pdb_e2e`）；
> 3. `p6_stats.py` 改用 `complete/sent`，输出
>    `run,ues,frames,satisfied,satisfied_pct,mean_fsr_paper,mean_fsr_e2e,dropped_frames`
>    写到 `summary2.csv`（旧的 `summary.csv` 保留原样）。
>
> **已知偏差**：丢弃粒度是 **SDU**（到达即判）而非论文的"整帧剩余 SDU"，
> 但一帧的 SDU 背靠背到达，实际影响很小；已在偏差声明里登记。
>
> **验证**：6 UE/cell 两条 → `p6-6-conv` 满意 **96.83%**（FSR_paper 99.82%，e2e 93.73%）、
> `p6-6-rtsr` 满意 **100%**（99.99% / 99.94%）——与论文"<17 UE/cell 两方案都 >90%"一致。

## 5. 成本模型（2026-11-03 实测修正）

> **实测成本随负载非线性上升**（单位：墙钟秒 per cell·UE·仿真秒）：

| 负载状态 | 成本 c | 依据 |
|---|---:|---|
| 低载（≤5%） | 0.12 | 21 cell / 1 UE/cell / 3 s = 157 s（optimized）|
| 中载（~65%，12 UE/cell） | ~0.36 | 由饱和点内插 |
| **饱和（≥95%，18 UE/cell 传统）** | **0.61** | `p6-18-conv` 实测：仿真 0→0.5 s 花 1305 s，边际 4800 s/仿真秒 |

**为什么不是常数**：低载时大部分 UE 没数据，调度器基本空闲；饱和时每个 slot
都要为 378 个 UE 跑调度 + HARQ + AMC，单位成本是低载的 **5 倍**。

### 单条 run 的墙钟（21 cell，6 s，1 s 预热 → 276 帧/UE）

| UE/cell | UE 数 | 单条 | 两条（RTSR + 传统）|
|---:|---:|---:|---:|
| 6 | 126 | 0.9 h | 1.8 h |
| 12 | 252 | 3.2 h | 6.4 h |
| 18 | 378 | **8.1 h** | **16.2 h** |
| 26 | 546 | 11.7 h | 23.4 h |

> `ThreeGppChannelModel::UpdatePeriod`（默认 0 = 只在 LoS/NLoS 变化时重建）
> 不是提速杠杆：设 5 ms 反而慢 ~15 倍。默认值意味着小尺度信道在整段仿真里准静态，
> 已写入偏差声明。

## 7. 抗中断

- run 级幂等：`results/p6/<run>/DONE` 存在即跳过；随时 Ctrl-C 再重跑同一条命令；
- run 内检查点：`--checkpointEveryMs`，被杀也留下到最后一次 flush 的数据；
- **单次 run 不可续跑**（ns-3 无 checkpoint/restore）；
- detached 运行（`setsid nohup`），脱离会话；
- **已加（步骤 1）**：`--progressEveryMs N` —— 每 N ms 仿真时间写一次 `progress.txt`：
  `simulated_ms / planned_ms / wall_s / wall_per_sim_s / eta_s`。只写一行，成本可忽略；
  与 `--checkpointEveryMs`（全量刷盘，546 UE 时很贵）**分开控制**。
- **已加（步骤 1）**：`--enablePing=0`（关掉纯诊断的 ping）、`--flowmonProbes=0`
  （XML 不写逐包 probe：实测 21 cell/21 UE 从 ~300 KB 降到 120 KB）。

## 11. 已知坑

1. **TDD 必须在建 PHY 前用属性设**（`SetGnbPhyAttribute("Pattern", ...)`）；
   在 t=0 调度 `SetPattern` 会 `Negative delay` abort。
2. CSV 只在 run 结束/检查点时写 → 已加 `--checkpointEveryMs`。
3. 短跑有接入偏差 → 已加 `--warmupMs`（P6 用 1000）。
4. 低载满意率被落点运气主导（G0：90.48% vs 95.24%）。
5. 本机墙钟不稳定（同配置 27 s ↔ 205 s）。
6. **UE 接入错峰不可行（已回退）**：把 `AttachToEnb` 推迟到 t>0 会让 UE PHY 的
   `StartEventLoop`（安装时就排在 t=0）先于 `RegisterToEnb/SetNumerology` 运行，
   `DoSetInitialBandwidth()` 直接 abort（`initialBandwidthWithOverhead == 0`，numerology 仍为 0）。
   要做必须把 `NrHelper::AttachToEnb` 拆成"先注册、后 NAS 连接"，属较大改动，暂缓。
