# 阶段 A 结果：量化波束网格

> 2026-11-19。阶段 A（Level 1：只改波束编号，不改波束矢量）的完整实验结果。
> 结论：**根因假设被证实，但 OFDMA 仍然赢不了 TDMA——这是更强的结论。**

## 1. 实现

新增 `QuantizedDirectPathBeamforming`（`src/nr/model/ideal-beamforming-algorithm.{h,cc}`）：

- 继承 `DirectPathBeamforming`，波束**矢量**仍是逐 UE 精确导向
- 额外按几何位置量化出 `BeamId`：方位角与俯仰角各按 `BeamGridDeg` 分格
- 编号从 1 起，避开 `BeamId::GetEmptyBeamId()` 的 `(0, 0)`

仿真侧新增两个开关：

```bash
--bfMode=quantized        # 启用（默认 ideal）
--beamGridDeg=15          # 网格宽度（度），默认 15
```

**没有改调度器、没有改 PHY、没有改信道模型。**

## 2. 验证：波束组数确实变多了

`[BEAMGRP]` 打印（稳态 0.9 s，3 小区 / 12 UE/cell）：

| 配置 | `activeDl.size()` | 每组 UE 数 |
|---|---:|---|
| `ideal`（基线）| **1** | 9 |
| `grid60` | 2 | 5 / 4 |
| `grid30` | 4 | 3 / 3 / 3 / 3 |
| `grid15` | **10** | 多数为 1 |

`grid15` 的实际打印：

```
[BEAMGRP] activeDl.size()=10 symAvail=11
  beam=[Sector: 16, elevation: -0.261799] ues=1
  beam=[Sector:  9, elevation: -0.261799] ues=1
  beam=[Sector: 16, elevation: -0.523599] ues=1
  ...
```

## 3. 主结果：BLER 随波束组数单调下降

| 配置 | 波束组 | BLER | 交付率 | Mbps/cell |
|---|---:|---:|---:|---:|
| `ideal`（基线）| 1 | **27.57%** | 58.8% | 185 |
| `grid60` | 2 | 14.81% | 68.8% | 185 |
| `grid30` | 4 | 8.12% | 73.6% | 164 |
| `grid15` | 10 | **2.47%** | 78.6% | 137 |
| **`tdma-qos`（对照）** | — | **2.39%** | **89.2%** | **186** |

**BLER：27.57 → 14.81 → 8.12 → 2.47，与波束组数 1 → 2 → 4 → 10 严格对应。**

这直接证实了根因：**BLER 就是"同一符号里有几个 UE 共享一个波束"的函数。**

## 4. 但 OFDMA 仍然输给 TDMA

| 指标 | 最好的 OFDMA（grid15）| TDMA | 差距 |
|---|---:|---:|---:|
| BLER | 2.47% | 2.39% | 持平 |
| **交付率** | **78.6%** | **89.2%** | **−10.6 pp** |
| **吞吐** | **137 Mbps/cell** | **186 Mbps/cell** | **−26%** |

### 为什么反而更慢

看调度器的早退条件（`nr-mac-scheduler-ofdma.cc` 的 `AssignDLRBG`）：

```cpp
while (resources > 0)
{
    std::sort(ueVector.begin(), ueVector.end(), GetUeCompareDlFn());
    ...
    if (tbSize >= std::max(bufQueueSize, 10U)) { /* 跳过这个 UE */ }
}
```

**波束组越多，每组里的 UE 越少。** 当一组只有 1 个 UE 时，它的缓冲一旦被满足，
这一组的 RBG 分配就提前结束，**该符号的剩余 RBG 被浪费**。

- 基线（1 组 9 UE）：组内 UE 多，循环能一直分到所有缓冲都满足 → 符号填满
- grid15（10 组各 1 UE）：每组很快就满足 → 每个符号都填不满

**换句话说：OFDMA 想要"同符号多用户"来填满符号，但模拟波束不允许这些用户各自成束。
两者不可兼得。**

## 5. 结论

**这是一个比"OFDMA 坏了"更强的结论：**

> 在模拟波束（每符号一个波束）约束下，OFDMA **无论怎么分组**都赢不了 TDMA。
> 分组越细，BLER 越好但符号填充越差；分组越粗，填充越好但 BLER 越差。
> **TDMA 恰好落在最优端**——它给每个 UE 独立的符号和完整的波束，不需要在两者间取舍。

我们的实验是**构造性证明**：不是"我们没调好 OFDMA"，而是"我们实现了正确的分组，
它依然输"。

## 6. 阶段 A 验收

| 判据 | 目标 | 实际 | 结果 |
|---|---|---|---|
| BLER | < 10% | 8.12%（grid30）/ 2.47%（grid15）| ✅ |
| 容量 | ≥ 120 Mbps/cell | 137（grid15）| ✅ |
| 每符号 UE 数 | ≤ 3 | 峰值 2（grid15）| ✅ |
| **超过 TDMA** | 期望 | **未达到**（137 vs 186）| ❌ |

**三条达标，一条未达。** 未达的那条不是实现问题，是物理约束。

## 7. 对阶段 B 的含义

阶段 B（数字波束 / 逐 RBG 预编码）能解决的是"同符号内多 UE 各自成束"，
从而**同时**获得低 BLER 和高填充率。

**但要注意**：阶段 B 的前提是"波束可以按频率变化"。在模拟移相器上这是物理做不到的，
必须换掉天线模型。改了之后，仿真的物理真实性会下降——需要如实说明。

**建议**：在进入阶段 B 之前，先想清楚论文里怎么表述。
当前结果已经足以支撑一个清晰的技术结论（见第 5 节），
阶段 B 的边际收益是"容量数字更接近论文"，边际成本是"偏离现成仿真器 + 物理真实性下降"。
