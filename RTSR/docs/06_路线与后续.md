## 2. 为什么阶段二不能用 ns-3

实测单位成本 **1.33 墙钟秒 / (cell × UE × 仿真秒)**，且 ns-3 单线程：

```
1000 s × 21 cell × 546 UE = 1,147 万单位 × 1.33 s = 175 天/点
```

**加核无效**（单点单线程），所以只能换工具。

| 工具 | 1000 s 单点 | 迁移成本 |
|---|---:|---|
| Vienna 5G SL（MATLAB）| ~1.6 h | 重写业务模型，2–3 周 |
| Simu5G（ns-3 模块）| ~64 h | 复用 C++，1 周 |
| 自写 Python/MATLAB SL | 视实现 | 3–4 周 |

**建议**：要 1000 s → Vienna；要省事 → Simu5G 跑 200 s（12,000 帧/UE 已足够）。

## 4. 成本模型（规划用）

> 墙钟 ≈ c × cells × UEs × 仿真秒

| 负载 | c | 说明 |
|---|---:|---|
| 低载 ≤5% | 0.12 | 基准 |
| 中载 ~65% | 0.36 | 内插 |
| 饱和 ≥95% | 0.61 | 实测 |

单点实测（21 cell，6 s）：6 UE/cell 3.9 h；9 = 6.5 h；12 = 14.3 h；18 = 17.6 h。

**并行上限**（16 核 / 15 GB）：小 run 6–8 路、中 run 5 路、大 run 3–4 路；
超过 4–5 路单条会慢 20–30%，总吞吐反而下降。

## 5. 阶段二的标定方法（关键）

1. 在 SL 仿真器里跑 **6 s × 21 cell × {6, 12, 18}**，与阶段一同配置；
2. 调链路抽象参数（SINR→BLER 表、波束模型），直到：
   - 6 UE/cell：两方案 >90%；
   - 12 UE/cell：传统崩、RTSR 稳；
3. **标定通过后**才把时长拉到 1000 s；
4. 报告中同时给出两阶段的数字，并说明"阶段一解释机制、阶段二给出统计结论"。
