## 1. 环境

| 项 | 值 |
|---|---|
| 系统 | WSL2 Ubuntu（Windows 宿主机）|
| ns-3 | 3.39，`~/code/ns-allinone-3.39/ns-3.39` |
| 5G-LENA | nr 模块（已集成）|
| 二进制 | `build/src/nr/examples/ns3.39-cttc-nr-traffic-3gpp-xr-optimized` |
| 构建档 | **optimized**（比 default 快 1.91×，结果逐位一致）|
| 机器 | 16 核 / 15 GB（WSL 默认拿宿主机一半）|

## 2. 编译

```bash
cd ~/code/ns-allinone-3.39/ns-3.39
./ns3 configure --build-profile=optimized   # 只需一次
./ns3 build                                  # 全量约 7 分钟（16 核）
```

改完 `rtsr-simulation.cc` 后的增量编译：

```bash
cp ~/code/EMT-Pytorch-ECCV2022/RTSR/rtsr-simulation.cc src/nr/examples/cttc-nr-traffic-3gpp-xr.cc
touch src/nr/examples/cttc-nr-traffic-3gpp-xr.cc
./ns3 build          # 约 30 秒
```

> 注意：仓库里的 `rtsr-simulation.cc` 是**源文件**，`./ns3 build` 编译的是
> `src/nr/examples/cttc-nr-traffic-3gpp-xr.cc`，所以每次改动都要 copy 过去。

## 3. 运行

### 3.1 单条（调试用）

```bash
BIN=~/code/ns-allinone-3.39/ns-3.39/build/src/nr/examples/ns3.39-cttc-nr-traffic-3gpp-xr-optimized
$BIN --trafficModel=paper --preset=paperTable3 --scheme=rtsr \
     --sectorized=1 --numSectors=3 --siteRings=1 --statsRings=1 \
     --uePerCell=6 --appDuration=6000 --indoorRatio=0.8 --ueSpeedKmh=3 \
     --tddPattern=DDDSU --warmupMs=1000 --progressEveryMs=250 \
     --checkpointEveryMs=5000 --enablePing=0 --flowmonProbes=0 --rngRun=1
```

### 3.2 批量（推荐）

```bash
cd ~/code/EMT-Pytorch-ECCV2022
# 串行
setsid nohup bash RTSR/scripts/p6_run.sh RTSR/scripts/p6_manifest.txt \
  > /tmp/p6.log 2>&1 &
# 并行（3 路）
setsid nohup bash RTSR/scripts/p6_run_parallel.sh \
  RTSR/scripts/p6_manifest_batch2.txt 3 > /tmp/p6_batch2.log 2>&1 &
```

manifest 格式：`<run id>|<额外参数>`，一行一个；`#` 开头为注释；
**结果目录里有 `DONE` 就跳过**，所以随时可以重跑同一条命令。

## 4. 看进度

```bash
cd ~/code/EMT-Pytorch-ECCV2022
bash RTSR/scripts/p6_status.sh          # 一条命令看全部
```

输出包含：在跑的进程（PID/墙钟/CPU）、每条 run 的进度与速率、剩余时间、
看门狗最后一行、`summary2.csv`。

**怎么判断"慢"还是"卡住"**：看 `results/p6/<run>/watchdog.log`

```
2026-11-05 15:04:47 pid=1536 sim_ms=5500 proc= 23:05:11 23:05:06
                                              ↑墙钟    ↑CPU时间
```

两个时间必须**一起涨**；墙钟涨而 CPU 不涨 = 机器被挂起或降频。

## 5. 产物说明

| 文件 | 内容 |
|---|---|
| `run.log` | 仿真标准输出（含各层汇总）|
| `checkpoint.txt` | 检查点状态（`complete,1` 表示正常结束）|
| `progress.txt` | 心跳：仿真时间 / 墙钟 / 速率 / ETA |
| `watchdog.log` | 每 5 分钟一行（墙钟 + 仿真时间 + CPU）|
| `frame_stats_port*_ue*.csv` | 每 UE 的逐帧记录 |
| `frame_per_ue.csv` | 每 UE 汇总（sent / seen / complete / in_pdb_e2e）|
| `source_frames.csv` | 帧源总发送数（FSR 分母）|
| `rlc_drops.csv` | RLC 丢弃（帧号 → SDU 数）|
| `flowmon.xml` | FlowMonitor 逐流统计 |
| `mac_tb.csv` / `phy_tb.csv` | MAC/PHY 汇总（TB 数、BLER、SINR）|
| `layer_report.md` | 五层合并报告（`layer_stats.py` 生成）|
| `summary_line.txt` | 该 run 的满意率行（由父进程合并进 `summary2.csv`）|

## 6. 排错速查

| 症状 | 原因 | 处理 |
|---|---|---|
| `Negative delay` abort | TDD `SetPattern` 在 t=0 调用 | 建 PHY **前**用属性设置 |
| `initialBandwidthWithOverhead == 0` | UE PHY 先于 attach 启动 | 不要推迟 attach |
| 两设备同坐标 abort | 三扇区共址 | 每扇区偏移 1 m |
| 心跳长时间不动 | 机器睡眠/降频 | 查 `watchdog.log` 的 CPU 时间 |
| 只有部分 run 启动 | 并行 runner 目录未建 | 已修（先 `mkdir -p`）|
| FSR 为负 | `layer_stats` 重叠计数 | 已修 |
| 满意率异常低 | 用了端到端口径 | 用 `complete/sent` |

## 7. 统计脚本

```bash
# 单 run 的论文口径满意率
python3 RTSR/scripts/p6_stats.py RTSR/results/p6/p6-12-conv

# 五层报告（覆盖生成）
python3 RTSR/layer_stats.py --dir RTSR/results/p6/p6-12-conv \
        --out RTSR/results/p6/p6-12-conv/layer_report.md
```

## 8. 资源约束（决定并行度）

| run 规模 | 单条内存 | 建议并行数 |
|---|---:|---:|
| 126 UE | ~0.9 GB | 8 |
| 189 UE | 1.05 GB | 6 |
| 252 UE | ~1.8 GB | 5 |
| 378 UE | 2.9 GB | 4 |

CPU 不是瓶颈（16 核，每仿真单线程）；**内存和内存带宽**是瓶颈。
超过 4–5 路并行时，单条会慢 20–30%，总吞吐反而下降。
